# מערכת ניהול קורס קק"ס

מערכת פנימית למפקד הקורס ולסגל שמרכזת במקום אחד את כל המשימות, האחריות, הדד-ליינים ותמונת המצב של הקורס - מהירה יותר מהודעת וואטסאפ.

המערכת בנויה סביב שלושה עקרונות מהאפיון: **אחריות** (לכל משימה אחראי ראשי אחד), **זמן** (אין משימה בלי דד-ליין) ו**תמונת מצב** (ניהול לפי חריגים - הצבע מופיע רק איפה שצריך להסתכל).

## פריסה

### Vercel + Supabase (חינם) - הפריסה הפעילה

האתר רץ ב-https://kks-roan.vercel.app: השרת כפונקציה ב-Vercel (פרנקפורט), והנתונים ב-Supabase (פרויקט `kks-course`, פרנקפורט). כל שינוי נשמר עם בדיקת גרסה, כך ששני אנשים ששומרים באותו רגע לא דורסים זה את זה, ועדכונים בין משתמשים מגיעים תוך כמה שניות. כל דחיפה לענף מעלה גרסה חדשה אוטומטית.

אין סוד להגדיר: הפונקציה ב-Supabase (`supabase/functions/kks-store`) מקבלת רק בקשות שנושאות את אסימון הזהות ש-Vercel מנפיק לפונקציות של הפרויקט (OIDC), ובודקת את החתימה, את הצוות, את הפרויקט ואת סביבת הייצור. הטבלאות סגורות לכל גישה אחרת (RLS בלי הרשאות).

להקמה מחדש בחשבון אחר:
1. ב-Supabase מריצים את `supabase/migrations/0001_kks_storage.sql`, ומעלים את `supabase/functions/kks-store` (עם verify_jwt כבוי) אחרי עדכון מזהי הצוות והפרויקט ב-Vercel שבראש הקובץ.
2. ב-Vercel מייבאים את הריפו (הגדרות הבנייה ב-`vercel.json`). אם כתובת הפונקציה שונה, מגדירים `KKS_STORE_URL`.
3. נכנסים לכתובת ומשלימים מיד את מסך הקמת הקורס.

דרך חלופית בלי פונקציה (בפריסה הפעילה היא סגורה, כדי שלא יישאר במסד שום דבר שאפשר לקרוא לו מבחוץ): משתני הסביבה `SUPABASE_URL`, `SUPABASE_KEY` (המפתח הציבורי) ו-`KKS_SECRET`, עם הגדרת הסוד ב-Supabase:
```sql
insert into kks_secret values (1, encode(sha256(convert_to('הסוד-שלכם', 'UTF8')), 'hex'));
```

קובץ מצורף מוגבל ל-4MB (מגבלת Vercel). בתוכנית החינמית של Supabase פרויקט שלא נעשה בו שימוש שבוע נכנס להשהיה, ומחזירים אותו בלחיצה בלוח הבקרה.

המסד נשמר באחסון דחוס (בערך פי 9 קטן יותר - כל שמירה וטעינה מעבירות פחות). **חזרה לגרסה קודמת ב-Vercel (Rollback):** אפשר לחזור לכל גרסה מ-"Read compressed copies of the database (step 1 of 2)" ואילך; גרסה ישנה ממנה לא יודעת לקרוא את המסד הדחוס.

### בלחיצה אחת (Render)

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/itai360/KKS)

הכפתור יוצר שירות לפי `render.yaml`: כתובת HTTPS קבועה (`https://kks-course-XXXX.onrender.com`) ודיסק קבוע למסד הנתונים ולקבצים. במהלך ההקמה Render מבקש שם משתמש וסיסמה לחשבון המפקד (`ADMIN_USERNAME`, `ADMIN_PASSWORD`) וכתובת קשר להתראות (`PUSH_CONTACT`). דיסק קבוע דורש תוכנית בתשלום (Starter). אפשר לחבר דומיין משלכם מהגדרות השירות ב-Render.

### שרת עם דומיין ו-HTTPS

שרת לינוקס קטן עם Docker (מספיק 1 ליבה ו-1GB זיכרון), ודומיין שרשומת ה-DNS שלו מצביעה על השרת. פורטים 80 ו-443 פתוחים.

```bash
git clone <הריפו> kks && cd kks
cp .env.example .env      # לערוך: DOMAIN, ADMIN_USERNAME, ADMIN_PASSWORD, PUSH_CONTACT
docker compose up -d
```

Caddy מנפיק ומחדש תעודת HTTPS אוטומטית, והמערכת זמינה ב-`https://<DOMAIN>`. HTTPS נדרש גם להתקנה כאפליקציה בטלפון וגם להתראות Push.

עדכון גרסה: `git pull && docker compose up -d --build`. נתוני הדגמה (רק בהתקנה ניסיונית): `docker compose exec app node dist/server/seed.js --reset`.

### הרצה פשוטה בלי דומיין

```bash
docker build -t kks .
docker run -d -p 3000:3000 -v kks-data:/data --name kks kks
```

מתאים לרשת פנימית או לניסיון. בלי HTTPS הדפדפן לא יאפשר התראות לטלפון.

### גיבוי

כל הנתונים (מסד SQLite וקבצים מצורפים) נשמרים בתיקייה אחת (`DATA_DIR`, בדוקר: הווליום `kks-data`). המערכת שומרת בעצמה גיבויים של המסד בתיקייה `snapshots` שבתוכה (בפריסה ב-Vercel - באחסון הקבצים ב-Supabase), ומפקד הקורס משחזר מהם או מוריד עותק מלא מהגדרות ← גיבויים ושחזור. קורס שהסתיים נשמר שם באותה דרך (קורסים קודמים) ולא נמחק לעולם. לגיבוי מלא כולל קבצים מצורפים - להעתיק את כל התיקייה.

### משתני סביבה

| משתנה | ברירת מחדל | הסבר |
|---|---|---|
| `PORT` | `3000` | פורט השרת |
| `DATA_DIR` | `data` | מיקום מסד הנתונים והקבצים |
| `COOKIE_SECURE` | `false` | `true` כשהמערכת מאחורי HTTPS (מוגדר אוטומטית ב-docker compose) |
| `SESSION_DAYS` | `30` | תוקף התחברות |
| `MAX_UPLOAD_MB` | `25` | גודל קובץ מצורף מרבי |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` / `ADMIN_NAME` | - | יצירת חשבון מפקד אוטומטית בהפעלה ראשונה (במקום מסך ההקמה) |
| `PUSH_CONTACT` | `mailto:admin@example.com` | כתובת קשר שנשלחת לשירותי ה-Push של הדפדפנים. מפתחות ה-Push נוצרים אוטומטית ונשמרים במסד |
| `GOOGLE_CLIENT_ID` | - | מפעיל כניסה עם Google. יוצרים OAuth Client מסוג Web application ב-Google Cloud Console עם `https://<DOMAIN>` כ-Authorized JavaScript origin, ומגדירים מייל לכל איש סגל בהגדרות ← אנשי סגל |
| `GOOGLE_HOSTED_DOMAIN` | - | מגביל את הכניסה עם Google לחשבונות מדומיין ארגוני אחד |

**חשוב:** אם המערכת חשופה לרשת, יש להשלים את מסך ההקמה מיד לאחר ההפעלה הראשונה (או להגדיר `ADMIN_USERNAME`/`ADMIN_PASSWORD`, ולהחליף את הסיסמה אחרי הכניסה הראשונה), ולהפעיל מאחורי HTTPS.

## גרסת הדגמה בדפדפן

```bash
npm run build:demo   # dist/demo/kks-demo.html
```

קובץ HTML אחד שמכיל את האפליקציה ואת השרת עצמו: אותו קוד שרת בדיוק (`server/src`) רץ בתוך הדף, עם SQLite שמקומפל ל-JavaScript (sql.js). הבקשות של האפליקציה (`/api/...`), העדכונים בזמן אמת וקישורי הקבצים מנותבים לשרת שבדף במקום לרשת, והנתונים נשמרים בדפדפן (IndexedDB). בפתיחה הראשונה נוצר קורס לדוגמה עם תאריכים של היום, ובמסך הכניסה יש כניסה בלחיצה כמפקד או כמפק"צ.

מתאים להצגה ולהתנסות, לא לעבודה של צוות: כל דפדפן מחזיק עותק נפרד של הנתונים, ואין התראות לטלפון או כניסה עם Google. לעבודה משותפת של הסגל - פריסה על שרת (למעלה).

`dist/demo/preview.html` הוא אותו דף עם מדיניות אבטחה (CSP) קפדנית, לבדיקה מקומית. כדי שהדף יוכל להוריד קבצים (ייצוא לאקסל, שמירת קובץ מצורף) הוא משתמש ביכולת השמירה של המארח כשהיא זמינה (`demo/download.ts`).

- "היום", "השבוע" ומשימות חוזרות מחושבים לפי אזור הזמן של הקורס (ברירת מחדל `Asia/Jerusalem`), בלי קשר למיקום השרת.
- "באיחור" אינו סטטוס שמור אלא מצב מחושב, כך שהסטטוס האמיתי ("בטיפול", "ממתין") לא הולך לאיבוד.
- מוכנות שבוע = משימות שהושלמו / כלל המשימות שלא בוטלו, ללא משימות שגרה חוזרות.
- הגנות: סיסמאות ב-scrypt, עוגיית סשן httpOnly, הגנת CSRF, הגבלת ניסיונות כניסה (5 בדקה; הנעילה נשמרת במסד, כך שהיא חלה על כל המופעים בפריסה ב-Vercel), בדיקת הרשאה בכל קריאה (כולל הורדת קבצים), וקבצים שהועלו מוצגים בדפדפן רק אם הם תמונה או PDF.
- נגישות: בדיקת axe (WCAG 2 AA) על כל המסכים, למפקד ולאיש סגל, במחשב ובטלפון ועם חלונות פתוחים - בלי ממצאים. לכל גוון יש צבע טקסט כהה מספיק (ניגודיות 4.5:1 ומעלה), ופסי התקדמות ונקודות בגרף מוקראים עם תיאור.
- חיבור: כשאין חיבור לשרת יותר מכמה שניות מופיעה הודעה (גם בטלפון), וכשעולה גרסה חדשה בזמן שהאתר פתוח - הודעה, והגרסה נטענת במעבר הבא בין מסכים.
- טעינה: עם האתר יורדים רק מסך הבית, הכניסה ו"המשימות שלי" (כ-112KB דחוס במקום 178KB); שאר המסכים יורדים ברקע כמה שניות אחרי הכניסה, אחד אחרי השני (לא כשהטלפון במצב חיסכון בנתונים), כך שמעבר בין מסכים מיידי ולשונית פתוחה ממשיכה לעבוד גם אחרי עדכון. אם קובץ של מסך כבר לא קיים בשרת (לשונית ישנה אחרי עדכון), הדף נטען מחדש פעם אחת, ואם גם זה לא עוזר מופיעה הודעה עם "נסה שוב".
